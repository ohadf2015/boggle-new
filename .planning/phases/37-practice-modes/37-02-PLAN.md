  <behavior>
    **useMatchingGame hook:**
    - Input: VocabularyWord[] (words with definitions)
    - Shuffles words and definitions into two separate columns
    - Tracks which pairs have been matched (matched: Set of word strings)
    - Tracks current attempt count and correct count
    - `checkMatch(wordId, definitionId)` -> returns {correct: boolean}
    - When all pairs matched: isComplete = true, calculates accuracy
    - Returns: { wordColumn, definitionColumn, matchedPairs, checkMatch, isComplete, accuracy, attempts, correctCount, resetGame }

    Test cases:
    - `checkMatch('apple', 'a fruit')` -> { correct: true } when apple's definition is 'a fruit'
    - `checkMatch('apple', 'a vehicle')` -> { correct: false }
    - After all pairs matched: isComplete === true
    - accuracy = correctCount / attempts
    - resetGame shuffles and clears state

    **WordMatchingPractice component:**
    - Two-column layout: words on left, definitions on right
    - Uses dnd-kit DndContext with PointerSensor and KeyboardSensor
    - Drag word from left column, drop onto definition on right column
    - Correct match: green border, checkmark, pair stays locked (cannot be dragged again)
    - Incorrect match: red border + shake animation, reverts after 1s
    - Progress shown: "X / Y pairs matched"
    - On completion: shows PracticeResultsCard with score and XP
    - CSS: `touch-action: none` on draggable items (iOS touch delay fix)
    - Neo-brutalist styling: border-neo, shadow-hard-sm, font-neo-display
    - RTL support: columns reverse for Hebrew
    - All text via t() — no hardcoded strings

    **Accessibility (WCAG 2.5.7):**
    - Keyboard: Arrow keys navigate items, Enter/Space to select, Tab to switch columns
    - dnd-kit KeyboardSensor with sortableKeyboardCoordinates
    - Alternative: tap-to-select mode (tap word, then tap definition) as fallback
  </behavior>
  <implementation>
    Follow TDD: write useMatchingGame tests first, then implement hook. Write component tests, then implement component.

    useMatchingGame:
    - Accept VocabularyWord[] array
    - On init, create shuffled arrays of { id, text } for words and definitions
    - Store matchedPairs as Map<string, string> (word -> definition)
    - checkMatch: compare word's actual definition with selected definition
    - Track attempts (total), correctCount
    - isComplete when matchedPairs.size === words.length

    WordMatchingPractice:
    - Props: { words: VocabularyWord[], onComplete: (results) => void, onBack: () => void }
    - Use dnd-kit's DndContext with closestCenter collision detection
    - Each word card is a Draggable, each definition slot is a Droppable
    - onDragEnd: extract active (word) and over (definition), call checkMatch
    - Feedback animation: AdaptiveMotion for correct/incorrect states
    - Use existing PracticeResultsCard on completion
    - When fewer than 4 pairs: show 2x2 grid instead of columns

    AVOID:
    - Don't use useSortable (we're matching, not sorting) — use useDraggable and useDroppable
    - Don't import from @dnd-kit/sortable for this mode — core DndContext is enough
    - Don't make all feedback animations mandatory — respect prefers-reduced-motion
  </implementation>
