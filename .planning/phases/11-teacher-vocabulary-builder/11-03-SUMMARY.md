# Phase 11 Plan 03: Teacher Dashboard Data Fetching Hooks Summary

**One-liner:** React hooks for classroom CRUD, vocabulary lesson management, and student progress tracking using Supabase queries with optimistic updates.

## What Was Built

Created comprehensive data fetching layer for Teacher Dashboard with:

### Supabase Query Utilities (lib/supabase/teacher.ts)
**Classroom queries:**
- `getClassrooms()` - Fetch all classrooms with member counts
- `getClassroom()` - Fetch single classroom with member count
- `createClassroom()` - Create classroom (join_code auto-generated by DB trigger)
- `updateClassroom()` - Update classroom name or language
- `deleteClassroom()` - Delete classroom (cascades to memberships)
- `joinClassroom()` - Student joins classroom via join code

**Lesson queries:**
- `getLessons()` - Fetch lessons for teacher (optionally filtered by classroom)
- `getLesson()` - Fetch single lesson with all details
- `createLesson()` - Create vocabulary lesson with word list
- `updateLesson()` - Update lesson metadata or words
- `deleteLesson()` - Delete lesson

**Progress queries:**
- `getStudentProgress()` - Fetch progress for student (all lessons or specific lesson)
- `getClassProgress()` - Fetch progress for all students in classroom for a lesson
- `updateProgress()` - Record word attempt and update mastery status

### React Hooks (4 hooks created)

**1. useClassrooms/useClassroom (hooks/useClassroom.ts):**
- `useClassrooms()` - Manage teacher's classroom list
  - CRUD operations: create, update, delete
  - Optimistic updates for instant UI feedback
  - Auto-refresh on auth state changes
- `useClassroom(id)` - Manage single classroom
  - Fetch classroom details with member count
  - Update/delete operations
  - Auto-refresh on mount
- `useJoinClassroom()` - Student enrollment
  - Join via 6-character code
  - Duplicate membership prevention

**2. useLessons/useLesson (hooks/useVocabularyLesson.ts):**
- `useLessons(classroomId?)` - Manage vocabulary lessons
  - CRUD operations: create, update, delete
  - Optional classroom filtering
  - Optimistic updates
- `useLesson(id)` - Manage single lesson
  - Fetch lesson with word list
  - Update operations
  - `addWords()` - Add words to lesson (for post-game word selection)
  - Duplicate word prevention

**3. useStudentProgress (hooks/useStudentProgress.ts):**
- Track individual student progress
- `recordAttempt()` - Record word attempt (correct/incorrect)
- Mastery tracking: 3+ correct attempts = mastered
- Optimistic updates for immediate feedback

**4. useClassProgress/useLessonStats (hooks/useStudentProgress.ts):**
- `useClassProgress()` - View all student progress for a lesson
- `useLessonStats()` - Aggregate statistics:
  - Completion rate
  - Average words attempted/mastered
  - Per-word difficulty metrics (accuracy rate)
  - Student engagement metrics

## Decisions Made

### 1. Custom Hooks Instead of React Query
**Decision:** Use useState/useCallback pattern instead of installing React Query

**Rationale:**
- React Query (@tanstack/react-query) not installed in project
- Existing hooks (useFriends, useCoins) use custom state management
- Installing React Query would be architectural change requiring user approval (Rule 4)
- Custom hooks provide same functionality (caching, optimistic updates)

**Impact:** Hooks follow established project patterns, no new dependencies

### 2. Optimistic Updates for All Mutations
**Decision:** Immediately update local state before server confirmation

**Rationale:**
- Provides instant UI feedback
- Supabase is fast (usually <100ms), but optimistic updates feel instant
- Easy to rollback on error (show error, refresh state)
- Follows pattern from useFriends hook

**Implementation:**
```typescript
// Create classroom optimistically
if (isMounted.current && data) {
  setState(prev => ({
    ...prev,
    classrooms: [{ ...data, member_count: 0 }, ...prev.classrooms],
  }));
}
```

**Impact:** Better UX, feels more responsive

### 3. Mastery Threshold: 3+ Correct Attempts
**Decision:** Word is "mastered" after 3 correct attempts

**Rationale:**
- 1 correct = too easy, could be luck
- 5+ correct = too strict, frustrating for students
- 3 correct = demonstrates understanding without excessive repetition
- Can be adjusted based on teacher feedback in future

**Impact:** Progress tracking reflects genuine learning

### 4. Separate Hooks for Lists vs Single Items
**Decision:** useClassrooms vs useClassroom, useLessons vs useLesson

**Rationale:**
- Follows React best practices (focused state management)
- List hooks handle arrays, single hooks handle individual items
- Prevents unnecessary refetching (updating one classroom doesn't refetch all)
- Matches existing patterns (no existing "useItem + useItems" pattern to contradict)

**Impact:** More granular control, better performance

## Technical Implementation

### Error Handling Pattern
All Supabase queries follow consistent error handling:
```typescript
try {
  const { data, error } = await supabase.from('table').select();
  if (error) {
    logger.error('Error message:', error);
    return { data: null, error: { message: error.message } };
  }
  return { data, error: null };
} catch (err) {
  const error = err instanceof Error ? err.message : 'Unknown error';
  logger.error('Exception:', error);
  return { data: null, error: { message: error } };
}
```

### Optimistic Update Pattern
All mutation hooks update state immediately:
```typescript
const { error } = await updateAPI(id, updates);
if (error) return { success: false, error: error.message };

// Optimistic update
if (isMounted.current) {
  setState(prev => ({
    ...prev,
    items: prev.items.map(item =>
      item.id === id ? { ...item, ...updates } : item
    ),
  }));
}
```

### State Management Pattern
All hooks follow useMounted pattern to prevent memory leaks:
```typescript
const isMounted = useMounted();

// In async functions
if (isMounted.current) {
  setState({ /* new state */ });
}
```

## Key Learnings

1. **Pattern Consistency Matters:** Following existing hook patterns (useFriends) made implementation straightforward and maintainable
2. **Optimistic Updates Are Simple:** Immediate state update + error rollback provides great UX without complexity
3. **Focused Hooks Are Better:** Separate hooks for lists vs single items prevents unnecessary refetching
4. **Error Handling Consistency:** Uniform error pattern across all queries makes debugging easier
5. **TypeScript Types Are Documentation:** Well-typed interfaces make hook usage obvious

## Performance Considerations

**Optimizations Applied:**
- Optimistic updates reduce perceived latency
- useMounted pattern prevents memory leaks
- Conditional queries (only fetch when authenticated)
- Member count aggregation in single query (not N+1)

**Future Optimizations:**
- Add pagination to lesson/progress lists if they grow large
- Consider React Query if caching strategy becomes complex
- Add background refetch for stale data (currently manual refresh only)
