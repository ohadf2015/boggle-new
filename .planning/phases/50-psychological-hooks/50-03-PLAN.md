  <behavior>
    Pure logic (blastSugarCrush.ts):
    - planSugarCrush(tileStates, gridSize) returns SugarCrushStep[]
    - SugarCrushStep: { row: number, col: number, convertTo: BlastTileType, delayMs: number, intensity: 'low' | 'medium' | 'high' }
    - Selects up to 8 uncleared standard tiles (random selection via Fisher-Yates on candidates)
    - First 2-3 tiles: convert to bomb (intensity: low, stagger 300ms)
    - Middle 2-3 tiles: convert to lightning or prism (intensity: medium, stagger 250ms)
    - Last 2 tiles: convert to rainbow or prism_prism-style big effect (intensity: high, stagger 200ms)
    - SUGAR_CRUSH_STAGGER_MS = 300 (base stagger, decreases with intensity)
    - Returns empty array if no standard uncleared tiles remain
    - Skips tiles that are already special (only converts 'standard' tiles)

    Hook (useBlastSugarCrush.ts):
    - isActive: boolean — true while sugar crush sequence is running
    - start(tileStates, gridSize, setTileStates, addExplosion, addScore): void
    - Plans sequence via planSugarCrush, then executes steps via staggered setTimeout chain
    - Each step: (1) convert tile type in tileStates, (2) trigger explosion visual, (3) add bonus score
    - After all steps complete, sets isActive=false and calls onComplete callback
    - Cleans up all timers on unmount
    - totalBonusScore accumulated across all steps

    Wiring in BlastGame.tsx:
    - When movesRemaining hits 0: instead of immediately marking isDeadEnd, start sugar crush sequence
    - During sugar crush: block grid input (similar to cascade blocking)
    - After sugar crush completes: add totalBonusScore to game state, THEN mark isDeadEnd and show results
    - The 500ms delay before onGameEnd remains AFTER sugar crush completes
  </behavior>

    4. Add translation key blast.sugarCrush to all 4 languages for potential banner text
  </implementation>
