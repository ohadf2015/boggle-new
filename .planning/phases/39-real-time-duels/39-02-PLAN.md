**Test cases to write (RED phase):**

1. **Disconnection grace period:**
   - On `disconnecting` event for player in active realtime duel: emits `duel:opponent-disconnected` to room with `{ opponentId, gracePeriodSeconds: 30 }`
   - Starts 30s server-side timer (use `jest.useFakeTimers()`)
   - After 30s without reconnection: auto-forfeits duel
   - Auto-forfeit sets duel status to `forfeited` in DB
   - Auto-forfeit awards opponent DUEL_WIN_REALTIME XP and disconnected player DUEL_LOSS_REALTIME XP
   - Auto-forfeit emits `duel:completed` to room with `{ winnerId: opponentId, reason: 'opponent_disconnected' }`
   - Disconnection of player NOT in active realtime duel: no grace period started (no-op)

2. **Reconnection:**
   - `handleReconnection(namespace, socket)`: cancels grace period timer
   - Emits `duel:opponent-reconnected` to room with `{ opponentId }`
   - Player rejoins duel room
   - No forfeit occurs after reconnection (timer cleared)

3. **Manual forfeit (`duel:forfeit`):**
   - Rejects invalid payload
   - Rejects if duel not active
   - Rejects if user not a participant
   - Sets duel status to `forfeited` with `forfeit_reason: 'manual'` in DB
   - Determines winner as the non-forfeiting player
   - Awards winner DUEL_WIN_REALTIME XP, forfeiter DUEL_LOSS_REALTIME XP (same as loss, not extra penalty)
   - Emits `duel:completed` to room with `{ winnerId, reason: 'forfeit', forfeitedBy: userId }`
   - Cleans up game state (if realtime game exists in memory)

**Implementation (GREEN phase):**

Create `disconnection.ts`:

1. **Grace period tracking:** `const gracePeriodTimers = new Map<string, NodeJS.Timeout>()` (userId -> timer)
   Export for testing.

2. **`registerDisconnectionHandlers(namespace, socket)`:**
   - Listen for `disconnecting` event on socket
   - Check if player has active realtime duel (query DB: `student_duels` where `(challenger_id = userId OR opponent_id = userId) AND status = 'active' AND duel_type = 'realtime'`)
   - If yes: notify opponent, start 30s timer
   - Timer callback: atomic forfeit (`.eq('status', 'active')` prevents double-completion)

   - Listen for `duel:forfeit` event:
     - Validate with `forfeitDuelSchema`
     - Verify participant + active status
     - Atomic update to `forfeited`
     - Award XP
     - Emit completion
     - Clean up realtime game state

3. **`handleReconnection(namespace, socket)`:**
   - Called when player reconnects to /duel namespace
   - Check gracePeriodTimers for userId
   - If exists: clearTimeout, delete from map
   - Query active duel, rejoin room
   - Emit `duel:opponent-reconnected` to room
   - Emit `duel:state-synced` to reconnecting player with current game state
