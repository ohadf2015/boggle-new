Create a React hook that connects to the /duel Socket.IO namespace. Follow the pattern of any existing useSocket hook in the codebase.

**Hook API:**
```typescript
interface UseDuelSocketReturn {
  socket: Socket | null;
  isConnected: boolean;
  // Lobby
  joinLobby: (classroomId: string) => void;
  leaveLobby: (classroomId: string) => void;
  // Challenge
  createChallenge: (opponentId: string, lessonId: string, classroomId: string) => void;
  acceptChallenge: (duelId: string) => void;
  declineChallenge: (duelId: string) => void;
  cancelChallenge: (duelId: string) => void;
  // Gameplay
  submitScore: (duelId: string, wordsFound: string[]) => void;
  // Event listeners (caller provides callbacks)
  onChallengeReceived: (cb: (data: ChallengeReceivedData) => void) => () => void;
  onLobbyUpdate: (cb: (data: LobbyUpdateData) => void) => () => void;
  onDuelAccepted: (cb: (data: DuelAcceptedData) => void) => () => void;
  onDuelDeclined: (cb: (data: { duelId: string }) => void) => () => void;
  onDuelCompleted: (cb: (data: DuelCompletedData) => void) => () => void;
  onScoreSubmitted: (cb: (data: ScoreSubmittedData) => void) => () => void;
  onError: (cb: (data: { message: string }) => void) => () => void;
}
```

**Implementation:**
- Use `useRef` for socket instance, `useState` for isConnected
- Connect to `${baseUrl}/duel` namespace on mount (get baseUrl from env or window.location)
- Disconnect on unmount
- Each action method emits the corresponding event (duel:create, duel:accept, etc.)
- Each `on*` method returns an unsubscribe function (listener cleanup pattern)
- Handle reconnection automatically (Socket.IO built-in)

```typescript
interface DuelCompletedData { winnerId: string | null; challengerScore: number; opponentScore: number; xpAwarded: { winner: number; loser: number; }; }
interface ScoreSubmittedData { playerId: string; score: number; wordsValidated: number; wordsRejected: number; }
```

**lobby.ts - exports `registerLobbyHandlers(namespace, socket)`:**

1. **duel:join-lobby** handler:
   - Extract classroomId from payload (validate with Zod)
   - Join room `duel:lobby:${classroomId}`
   - Store user info in a lobby tracking Map (classroomId -> Set of { userId, displayName, socketId })
   - Query pending duels for this student from DB (getPendingDuelsForStudent)
   - Emit `duel:lobby-state` to joining socket: { availableOpponents, pendingChallenges }
   - Broadcast `duel:lobby-update` to room: { availableOpponents } (updated list)

2. **duel:leave-lobby** handler:
   - Remove from lobby tracking Map
   - Leave room
   - Broadcast `duel:lobby-update` to room

3. **disconnect** handler (lobby-specific cleanup):
   - Remove from all lobby tracking Maps
   - Broadcast `duel:lobby-update` to affected rooms

Use a module-level `Map<string, Map<string, OpponentInfo>>` for tracking (classroomId -> userId -> info). This is an in-memory structure, acceptable for single-server deployment.
