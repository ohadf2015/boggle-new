1. Create migration `fe-next/supabase/migrations/20260215200000_award_education_xp.sql`:
   - CREATE OR REPLACE FUNCTION award_education_xp(p_student_id UUID, p_xp_amount INTEGER, p_lesson_id UUID DEFAULT NULL)
   - RETURNS void, LANGUAGE plpgsql, SECURITY DEFINER, SET search_path = public
   - CRITICAL: p_lesson_id defaults to NULL for backward compatibility with existing duel handler calls (realtime.ts:325, gameplay.ts:293, disconnection.ts:282) which pass only p_student_id + p_xp_amount
   - When p_lesson_id IS NOT NULL: UPSERT into student_lesson_progress (student_id, lesson_id, total_xp, total_practice_sessions, last_practice_date) with ON CONFLICT (student_id, lesson_id) DO UPDATE SET total_xp = total_xp + p_xp_amount, total_practice_sessions = total_practice_sessions + 1, last_practice_date = CURRENT_DATE
   - When p_lesson_id IS NULL: skip student_lesson_progress update (duel XP tracked separately)
   - The existing update_student_level() trigger (migration 062) fires automatically on total_xp update to recalculate current_level
   - GRANT EXECUTE to authenticated
   - Add COMMENT ON FUNCTION

2. Update `fe-next/app/api/education/practice/route.ts` PATCH handler:
   a. Add idempotency guard: In the existing session ownership check (line 282-287), expand the select to include `completed_at` along with `id, student_id`:
      `.select('id, student_id, completed_at')`
      After the ownership check, add: if `existing.completed_at` is truthy, return existing session early (200 with session data) to prevent double-awarding
   b. Expand the session update select (line 316) from `.select()` to `.select('*')` to ensure lesson_id is available in the returned session object
   c. After the successful session update (after line 317, before the return on line 324), add XP award block:
      - Guard: only if `completed` is true (from request body) AND session.xp_awarded > 0
      - Call `supabase.rpc('award_education_xp', { p_student_id: session.student_id, p_lesson_id: session.lesson_id, p_xp_amount: session.xp_awarded })`
      - On RPC error: log with `logger.error('Failed to award education XP:', xpError)` but do NOT fail the request (session already saved)
      - On success: log with `logger.info('EDUCATION', \`Awarded ${session.xp_awarded} XP...\`)`
   d. Do NOT change the import list (createClient, logger, z, NextRequest, NextResponse already imported)

Key pitfalls to avoid (from research):
- Use snake_case for RPC params: p_student_id, p_lesson_id, p_xp_amount (NOT camelCase)
- Guard on `completed` flag from request body (not `session.completed_at` which may be set by previous update attempts)
- Do NOT await the RPC call with try/catch that would affect the response -- use `const { error: xpError } = await ...` pattern
