## Cross-Phase Integration Issues

### 1. Wildcard Still in Canonical BlastTileType (TILE-06 + TILE-08 + SYNC-01)

**Root cause:** Phase 47 (plan 47-04) removed `case 'wildcard'` from game logic and removed wildcard from spawn distributions, but never edited `shared/types/blast.ts` to remove `'wildcard'` from the `BlastTileType` union or `BLAST_TILE_TYPE_LIST`. Phase 46 verification checked "no divergent type definitions" but didn't verify wildcard absence from the union.

**Impact chain:**
- `shared/types/blast.ts` line 24: `'wildcard'` in union (14 types, should be 13)
- `shared/types/blast.ts` line 41: `'wildcard'` in `BLAST_TILE_TYPE_LIST`
- `blast.test.ts` asserts `BLAST_TILE_TYPE_LIST.length === 14` and **includes** wildcard
- `mirrorGoldTier.test.ts` asserts list does **NOT** include wildcard — **contradictory**
- `blastMultiplayerConstants.ts` imports `BLAST_TILE_TYPE_LIST` for `BLAST_TILE_TYPES`
- MP overlay generation could produce wildcard tiles that fall through all switches silently

**Fix:** Remove `'wildcard'` from `BlastTileType` union and `BLAST_TILE_TYPE_LIST` in `shared/types/blast.ts`. Update `blast.test.ts` assertion to length=13 without wildcard. Fix any downstream compile errors.

### 2. Multiplayer Combo Sync Outbound Broken (SYNC-02)

**Root cause:** `BlastGame.tsx` defines `onWordWithComboType` prop and calls it when a combo is detected. But no parent component ever passes this prop:
- Singleplayer: `BlastView.tsx` renders `<BlastGame>` without `onWordWithComboType`
- Multiplayer: `InGameScreen` uses overlay grid, not `BlastGame` directly

The server-side handler exists (`wordHandler.ts` broadcasts `blastComboSync`), the Zustand listener exists (`usePlayerGameEvents`), the display path works (`triggerComboFlash`) — but the **outbound emission** (client → server with `comboType`) is never triggered.

**Fix:** Wire `onWordWithComboType` from `BlastGame` through the multiplayer word submission flow, or include `comboType` in the `submitWord` socket payload from `useWordSubmission`.

### 3. Combo Codex Supabase Sync Missing userId (SYNC-04)

**Root cause:** `BlastView.tsx` calls `useBlastComboDiscovery()` without passing `userId`. The hook accepts `{ userId }` and has Supabase sync logic, but without a userId it falls back to localStorage-only mode for all users.

**Fix:** Read authenticated user ID from auth context in `BlastView.tsx` and pass to `useBlastComboDiscovery({ userId })`.
