## CRIT (ship-blockers)

### C1 — Desktop layout = mobile-stacked at 1920px (sitewide)

**Routes**: `/en`, `/en/multiplayer`, `/en/adventure`, `/en/daily`, `/en/brain` (all desktop).

**Symptom**: content column ~600-700px centered in 1920px viewport. ~60-70% of horizontal space empty/wasted. Mode cards, mission cards, arena buttons all stacked vertically when a multi-column grid would fit naturally.

**Impact**: 38.9% of users (per GA4) see a single-column mobile layout on a desktop monitor. Conflicts with CLAUDE.md design context "Phone AND TV".

**Specifically broken**:
- `/en` home — 4 mode cards (Daily, Multi, Practice, locked-tier) stacked vertically; mascot bubbles drift to viewport edges 1300px from content.
- `/en/multiplayer` — Quick Start + Create Private Battle buttons in a narrow centered column; ~800px of black void below.
- `/en/brain` — anonymous user sees ONE small "Sign In to Track Your Gains" card in 1920×1080. ~95% empty.
- `/en/daily` — 2 quest cards stacked vertically; bottom half empty (decorative letters notwithstanding).

**Suggested fix sketch**:
- Home: use CSS grid `repeat(auto-fit, minmax(280px, 1fr))` for mode cards on `≥md`.
- Multiplayer: list/detail split — open arenas list (left) + quick-action panel (right) on `≥lg`.
- Brain (anonymous): show drill cards as preview grid even when not signed in; sign-in CTA becomes secondary.

### C2 — "Failed to load leaderboard" on /daily

**Route**: `/en/daily` (1920×1080 confirmed; 360×792 not visible because card scrolls off / gets clipped).

**Evidence**: red text inside LEADERBOARD card: "Failed to load leaderboard / Try Again". Issues badge incremented 2 → 4 on this route, confirming runtime errors fired.

**Likely cause**: daily-specific leaderboard fetch (`get_daily_leaderboard` or similar RPC) erroring or returning shape the client doesn't expect. (Investigation pending.)

## Methodology notes

- Single Playwriter session, sequential navigation (avoids Chrome tab collisions).
- Each route: setViewportSize → goto(domcontentloaded) → waitForPageLoad(5s) → fullPage screenshot → DOM probe (overflow, tap-targets, banner var, fixed-below-viewport, h1, CTA-in-fold heuristic).
- DOM probe runs in `page.evaluate()` so it sees the real layout post-hydration.
- Skip-link (1×1) excluded from tap-target count (intentional WCAG pattern).
- Tap-target threshold = 44×44 css px per WCAG 2.5.5 Level AAA / Material Design Touch Target.
