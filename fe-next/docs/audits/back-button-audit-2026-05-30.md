# Back-Button Audit — 2026-05-30

Automated audit of back-button / one-level-up navigation across **all 188 app routes** (Next.js App Router, `fe-next/app`). Each route's full component tree + layout chain was traced; flagged routes were independently re-verified to remove false positives. Parent routes were computed deterministically (longest existing path-prefix). Raw data: `back-button-audit-2026-05-30.findings.json`.

## Executive summary

Two systemic problems dominate:

1. **37 routes have NO back affordance at all** (20%) — but these are NOT equal priority. **9 are functional dead-ends** (app screens users navigate to and then can't leave one level up: party hub/join, custom puzzle browser, education sub-landings, the connections/education landings, etc.) — *these are the urgent ones*. 25 are SEO/marketing landing pages (in-scope since you asked for "all pages," but low urgency — they rely on in-content CTAs + the bottom nav). 3 are programmatic/dev/demo pages (auth callback, avatar-test, fanfare-demo…) where a back button is largely N/A. The global `GlobalBottomNav` is lateral tab nav (Quests/Friends/Home) — *not* a back button and does not go one level up.
2. **35 routes use history-based "back"** (19%) via `HeaderBackButton` / `useAndroidBackButton` / raw `router.back()`. `router.back()` follows the *browser history stack*, not the URL hierarchy. On a deep-link or page refresh `history.length === 1`, so `HeaderBackButton` falls back to **home**, over-shooting every intermediate level. Even with history, it returns to wherever the user came from — not guaranteed to be the parent.

Plus **9 routes** whose back control points to the wrong place (sibling, home-skipping-parent, or a non-existent route). Only **88 routes** (47%) navigate correctly one level up. 19 are intentionally back-less (home / immersive game / TV host views) with a cited exit mechanism.

## 6. Systemic recommendation

### Centralize on a hierarchy-aware back helper

Replace the fragmented back implementations (`HeaderBackButton`, `useAndroidBackButton`, ad-hoc `router.push`/`router.back()`) with a single source of truth:

```ts
// lib/navigation/parentRoute.ts
// Pure: compute the URL-hierarchy parent of a pathname (locale-aware).
export function parentRoute(pathname: string, lang: string): string {
  const segs = pathname.split("/").filter(Boolean);     // ["en","daily","archive","2026-01-01"]
  if (segs.length <= 1) return `/${lang}`;               // already at home
  segs.pop();                                            // drop one level
  return "/" + segs.join("/");
}

// hooks/useBackOneLevel.ts
export function useBackOneLevel() {
  const router = useRouter();
  const pathname = usePathname() || "/";
  const { language } = useLanguage();
  return useCallback(() => {
    const parent = parentRoute(pathname, language);
    // Optimization: if we genuinely came from the parent, back() preserves scroll/state.
    if (typeof document !== "undefined" && document.referrer) {
      try {
        const ref = new URL(document.referrer);
        if (ref.origin === location.origin && ref.pathname === parent) { router.back(); return; }
      } catch {}
    }
    router.push(parent);   // deterministic one-level-up — never over-shoots to home
  }, [router, pathname, language]);
}
```

Then point `HeaderBackButton` and `useAndroidBackButton` at `useBackOneLevel()`. Because ~25 pages render `<Header/>`, fixing `HeaderBackButton` alone repairs the bulk of the RISK_HISTORY set in one change. A handful of routes need a hand-mapped parent where the URL hierarchy lies (e.g. education sub-pages that belong under `/education`, results screens that belong to a lobby) — add a small `PARENT_OVERRIDES` map for those.

| --- | --- | --- | --- |
| **P0** | Build `parentRoute` + `useBackOneLevel`; rewire `HeaderBackButton` + `useAndroidBackButton` | 2–3 d | Fixes the bulk of the 35 RISK_HISTORY routes at once |
| **P1** | Add a back affordance to the 9 functional dead-ends (§1a: party hub/join, custom, education sub-landings, connections/education landings, daily-word-wheel…) | 1–2 d | Closes the worst UX dead-ends |

| **P3** | Add a top back link to the 25 SEO/landing + blog pages (§1b; push parent or `/<lang>`) | 1 d | Completeness; minor SEO/UX win |

### Lock it in with a test
Add a unit test over `parentRoute` for representative deep routes, and a lint/CI guard that fails when a new `page.tsx` ships without a reachable back affordance (or an explicit `INTENTIONAL_NONE` opt-out), so coverage does not regress.
