<task type="auto">
  <name>Task 2: Add BundleWatch for JavaScript bundle size tracking</name>
  <files>package.json</files>
  <action>
Install BundleWatch and configure bundle size limits.

1. Install BundleWatch:
```bash
npm install --save-dev bundlewatch
```

2. Add bundlewatch configuration to package.json:
```json
{
  "bundlewatch": {
    "files": [
      {
        "path": ".next/static/**/*.js",
        "maxSize": "250kb",
        "compression": "gzip"
      },
      {
        "path": ".next/static/**/*.css",
        "maxSize": "50kb",
        "compression": "gzip"
      }
    ],
    "defaultCompression": "gzip",
    "ci": {
      "trackBranches": ["main"]
    }
  }
}
```

3. Add npm script:
```json
{
  "scripts": {
    "bundle:check": "bundlewatch"
  }
}
```

WHY 250KB for JS: Research shows this is reasonable for a Next.js app with game features. Smaller is better but 250KB is achievable without aggressive code splitting.

WHY gzip: Matches how Vercel/CDN serves files. Raw size would be misleading.
  </action>
  <verify>
1. `npm ls bundlewatch` shows installed
2. `npm run bundle:check` runs (requires prior build: `npm run build`)
3. bundlewatch config appears in package.json
  </verify>
  <done>
BundleWatch installed and configured with 250KB JS / 50KB CSS limits using gzip compression.

<task type="auto">
  <name>Task 3: Create GitHub Actions performance workflow</name>
  <files>.github/workflows/performance.yml</files>
  <action>
Create a comprehensive performance CI workflow that runs all checks.

```yaml
name: Performance Checks

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  # Job 1: Bundle size check (fast, runs first)
  bundle-size:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: Check bundle size
        run: npm run bundle:check
        env:
          BUNDLEWATCH_GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

  # Job 2: Asset size validation (fast)
  asset-sizes:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Check asset sizes
        run: npm run assets:check

  # Job 3: Lighthouse CI (slower, runs in parallel)
  lighthouse:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: Run Lighthouse CI (Mobile)
        run: npm run lighthouse:ci:mobile
        env:
          LHCI_GITHUB_APP_TOKEN: ${{ secrets.LHCI_GITHUB_APP_TOKEN }}

      - name: Run Lighthouse CI (Desktop)
        run: npm run lighthouse:ci:desktop
        env:
          LHCI_GITHUB_APP_TOKEN: ${{ secrets.LHCI_GITHUB_APP_TOKEN }}

      - name: Upload Lighthouse artifacts
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: lighthouse-results
          path: .lighthouseci/
          retention-days: 7

  # Summary job: All checks must pass
  performance-gate:
    needs: [bundle-size, asset-sizes, lighthouse]
    runs-on: ubuntu-latest
    if: always()
    steps:
      - name: Check all jobs passed
        run: |
          if [ "${{ needs.bundle-size.result }}" != "success" ] || \
             [ "${{ needs.asset-sizes.result }}" != "success" ] || \
             [ "${{ needs.lighthouse.result }}" != "success" ]; then
            echo "Performance checks failed!"
            exit 1
          fi
          echo "All performance checks passed!"
```

Create the .github/workflows directory if it doesn't exist:
```bash
mkdir -p .github/workflows
```

Note: LHCI_GITHUB_APP_TOKEN is optional. Without it, Lighthouse CI still runs but won't post PR comments. BUNDLEWATCH_GITHUB_TOKEN uses the default GITHUB_TOKEN which is automatically available.
