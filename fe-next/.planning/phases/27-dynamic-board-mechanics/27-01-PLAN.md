  <behavior>
    The hook manages a state machine with phases: idle -> removing -> falling -> spawning -> checking

    Phase Timing:
    - REMOVING phase: 250ms (tiles fade out with scale animation)
    - FALLING phase: 250ms (tiles above fall into empty spaces)
    - SPAWNING phase: 250ms (new tiles spawn at top and fall in)
    - CHECKING phase: instant (check for new matches, loop or return to idle)

    State Interface:
    ```typescript
    interface CascadeState {
      phase: 'idle' | 'removing' | 'falling' | 'spawning' | 'checking';
      isProcessing: boolean;  // True when any phase is active (blocks input)
      iteration: number;      // Current cascade iteration (for safety limit)
      pendingRemovals: Set<string>;  // Tile IDs to remove
      fallingTiles: Map<string, number>;  // Tile ID -> fall distance in rows
      spawningTiles: string[];  // New tile IDs being spawned
    }
    ```

    API:
    - startCascade(tilesRemoved: string[]): Begin cascade with removed tiles
    - applyGravity(tiles: TileState[][]): Calculate which tiles fall and how far
    - spawnNewTiles(tiles: TileState[][], gridSize: number): Generate new tiles for empty spaces
    - checkForMatches(tiles: TileState[][]): Check if fallen tiles create new valid positions (stub - returns false for MVP)
    - reset(): Force reset to idle state

    Test Cases:
    - Single cascade completes in ~750ms (3 x 250ms phases)
    - Cascade blocks isProcessing during all phases
    - Gravity calculates correct fall distances (tiles above gaps fall)
    - Spawn generates correct number of new tiles
    - Safety limit stops after 10 iterations
    - Reset clears all state immediately
    - Phase transitions fire callbacks (onPhaseChange)
  </behavior>
  <implementation>

    4. Implement applyGravity to calculate fall distances

    7. Add safety limit (MAX_CASCADE_ITERATIONS = 10)
    8. Add onPhaseChange callback prop for UI coordination
    9. Handle reduced motion (instant transitions, 0ms delays)
  </implementation>
</feature>
