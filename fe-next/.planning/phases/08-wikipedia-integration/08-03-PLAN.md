## Goal

Harden the Wikipedia word pipeline against edge cases: duplicate word handling, AI validation timeouts, database errors, and validation error fallbacks.

## Context

**Current State:**
- Pipeline works for happy path
- Edge cases can cause silent failures or confusing errors
- No fallback when AI validation times out
- Duplicate word handling relies on database constraints (throws errors)

**What this adds:**
- Graceful handling of all identified edge cases
- Explicit fallback logic when AI unavailable
- Clear error messages for debugging
- Defensive programming throughout pipeline

## Requirements Coverage

- **FIX-01**: Wikipedia word extraction pipeline working (hardening)
- **FIX-02**: Words sync from admin dashboard to game dictionary (error handling)

## must_haves

Derived from phase goal "Wikipedia word extraction pipeline reliably syncs curated words to game dictionary":

1. Duplicate words across dates don't cause errors
2. AI validation timeout triggers format-only fallback for high-scoring words
3. Database errors are logged and don't break the pipeline
4. Each error scenario has specific, helpful error message
5. Pipeline continues processing remaining candidates after individual failures

**Add format-only validation fallback**

Update `utils/dailyChallenge/wikipediaWordProcessor.ts`:

```typescript
// Minimum score for format-only fallback validation
// Words with this score or higher can be approved without AI when AI is unavailable
const FORMAT_ONLY_FALLBACK_THRESHOLD = 85;

/**
 * Validate a word using AI service with fallback to format validation
 * When AI is unavailable, high-scoring words that pass format validation are approved
 *
 * @param word - Word to validate
 * @param language - Language code
 * @param score - Interestingness score (used for fallback decision)
 * @returns Whether the word is valid
 */
export async function validateWordWithAI(
  word: string,
  language: Language,
  score?: number
): Promise<{ valid: boolean; reason: string; source: 'ai' | 'format' }> {
  try {
    // Dynamic import to avoid circular dependencies
    const { gameAIService } = await import('@/lib/ai-service');

    // First try database-only check (fast)
    const dbResult = await gameAIService.checkDatabaseOnly(word, language);
    if (dbResult.source === 'database' && dbResult.isValid) {
      return {
        valid: true,
        reason: 'Dictionary validated',
        source: 'ai'  // Actually database, but same pipeline
      };
    }

    // If not in database, validate with AI and save if valid
    const result = await gameAIService.validateAndSaveWord(word, language);

    return {
      valid: result.isValid,
      reason: result.reason || (result.isValid ? 'AI validated' : 'AI rejected'),
      source: 'ai'
    };

  } catch (error) {
    const errorMessage = error instanceof Error ? error.message : 'Unknown error';
    console.warn(`[WordProcessor] AI validation error for ${word}:`, errorMessage);

    // FALLBACK: For high-scoring words, use format validation
    if (score !== undefined && score >= FORMAT_ONLY_FALLBACK_THRESHOLD) {
      const formatResult = validateGameWord(word, language);

      if (formatResult.valid) {
        console.log(`[WordProcessor] Using format-only fallback for ${word} (score: ${score})`);
        return {
          valid: true,
          reason: 'Format validated (AI unavailable)',
          source: 'format'
        };
      }
    }

    // Default to invalid on error for lower-scoring words
    return {
      valid: false,
      reason: 'AI validation unavailable',
      source: 'ai'
    };
  }
}
```

```typescript
/**
 * Store word candidates with defensive duplicate handling
 * Uses upsert with onConflict to handle duplicates gracefully
 */
async function storeWikipediaWordCandidates(
  language: Language,
  date: Date,
  candidates: Array<{ word: string; source: string; url?: string; score: number }>
): Promise<void> {
  const supabase = createClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.SUPABASE_SERVICE_ROLE_KEY!
  );

  const dateStr = date.toISOString().split('T')[0];

  // Process in batches to prevent timeout
  const BATCH_SIZE = 500;
  const batches = [];
  for (let i = 0; i < candidates.length; i += BATCH_SIZE) {
    batches.push(candidates.slice(i, i + BATCH_SIZE));
  }

  for (const batch of batches) {
    const records = batch.map(c => ({
      language,
      fetch_date: dateStr,
      word: c.word.toUpperCase(),
      source_article_title: c.source,
      source_article_url: c.url || null,
      interestingness_score: c.score,
      validation_status: 'pending' as const,
    }));

    try {
      const { error } = await supabase
        .from('wikipedia_word_candidates')
        .upsert(records, {
          onConflict: 'language,word,fetch_date',
          ignoreDuplicates: false  // Update existing records
        });

      if (error) {
        // Log but don't throw - continue with other batches
        console.error(`[WikiFetcher] Batch upsert error:`, error.message);
      }
    } catch (batchError) {
      console.error(`[WikiFetcher] Batch processing error:`, batchError);
      // Continue with next batch
    }
  }
}
```

```typescript
function logPipelineError(
  operation: string,
  error: unknown,
  context: {
    word?: string;
    language?: Language;
    score?: number;
    candidateId?: string;
  }
): void {
  const errorMessage = error instanceof Error ? error.message : String(error);
  const contextStr = JSON.stringify(context);

  console.error(`[WikiPopulator] ${operation} failed: ${errorMessage}`, {
    operation,
    error: errorMessage,
    ...context,
    timestamp: new Date().toISOString()
  });
}
```

```typescript
async function validateTopCandidates(
  candidates: Array<{ word: string; score: number; source: string; url?: string }>,
  language: Language,
  dateStr: string
): Promise<Array<{ word: string; score: number; source: string; url?: string }>> {
  const validated: Array<{ word: string; score: number; source: string; url?: string }> = [];
  const errors: Array<{ word: string; error: string }> = [];

  for (const candidate of candidates.slice(0, 10)) {
    try {
      const result = await validateWordWithAI(candidate.word, language, candidate.score);

      if (result.valid) {
        validated.push(candidate);

        // Update status in staging table
        await updateWordValidationStatus(language, candidate.word, dateStr, 'valid', candidate.score)
          .catch(err => logPipelineError('status-update', err, { word: candidate.word, language }));

        // Auto-promote high-scoring validated words
        if (candidate.score >= AUTO_PROMOTION_SCORE_THRESHOLD) {
          await promoteToDict(candidate.word, language, candidate.score)
            .catch(err => logPipelineError('auto-promotion', err, { word: candidate.word, language }));
        }
      } else {
        await updateWordValidationStatus(language, candidate.word, dateStr, 'invalid')
          .catch(err => logPipelineError('status-update', err, { word: candidate.word, language }));
      }

    } catch (error) {
      // Individual candidate failure - log and continue
      errors.push({
        word: candidate.word,
        error: error instanceof Error ? error.message : 'Unknown error'
      });
      logPipelineError('validation', error, { word: candidate.word, language, score: candidate.score });

      // For format-valid high-scoring words, still consider them validated
      if (candidate.score >= FORMAT_ONLY_FALLBACK_THRESHOLD) {
        const formatResult = validateGameWord(candidate.word, language);
        if (formatResult.valid) {
          validated.push(candidate);
          console.log(`[WikiPopulator] Added ${candidate.word} despite error (format valid, high score)`);
        }
      }
    }
  }

  if (errors.length > 0) {
    console.warn(`[WikiPopulator] ${errors.length} candidates had errors:`,
      errors.map(e => `${e.word}: ${e.error}`).join(', ')
    );
  }

  return validated;
}
```

## Edge Cases Covered

| Edge Case | Handling |
|-----------|----------|
| Duplicate word in dictionary | Skip promotion, log info |
| Same word different dates | Allow in staging, skip duplicate promotion |
| AI validation timeout | Fallback to format validation for score ≥85 |
| AI credentials missing | Same fallback behavior |
| Database save failure | Log error, continue with other candidates |
| Individual candidate error | Log, continue processing rest |
| Empty candidate batch | Return empty array, no error |

## Rollback Plan

These are defensive improvements that don't change happy-path behavior:
1. If fallback is too permissive, raise threshold from 85 to 90
2. If too strict, lower to 80
3. All changes are additive - can revert individual handlers
