For EACH critical and high severity bug in BUG-REGISTRY.md:

1. **Create a test file** (or add to existing) that reproduces the bug
2. **Name test clearly**: `should [expected behavior] (BUG-XXX)`
3. **Write Given-When-Then test** following the reproduction steps
4. **Run test** - it MUST FAIL (this proves we've captured the bug)

**Test Template:**
```typescript
describe('[Component] Bug Fixes', () => {
  // BUG-001: [Title from BUG-REGISTRY.md]
  test('should [expected behavior] (BUG-001)', () => {
    // GIVEN - Setup matching reproduction steps
    const { result } = renderHook(() => useSurvivalGameLogic({
      // Props matching bug scenario
    }));

    // WHEN - Action that triggers the bug
    act(() => {
      result.current.actions.handleWordSubmit('testword');
    });

    // THEN - Expected behavior (will FAIL until fixed)
    expect(result.current.state.score).toBe(expectedScore);
  });
});
```

**Focus Order:**
1. Critical bugs first (crashes, data loss)
2. High severity bugs (incorrect scoring, major UI)
3. Document which bugs have tests in BUG-REGISTRY.md

Run `npm run test:frontend -- --testPathPattern="daily"` after each test to confirm it fails.

1. **Analyze the root cause** - Use the bug reproduction to trace the issue
2. **Implement minimal fix** - Just enough to make the test pass

**Fix Guidelines:**
- Fix ONE bug at a time
- Don't refactor while fixing (that's the next step)
- Keep fixes minimal and focused
- If fix affects multiple components, verify each

**Common Fix Patterns:**
- Scoring bugs: Check calculation logic in survivalGameReducer.ts
- State bugs: Check useSurvivalGameLogic.ts state updates
- UI bugs: Check component render conditions
- Race conditions: Add proper async handling

After each fix:
- Run `npm run test:frontend -- --testPathPattern="daily"`
- Ensure the specific bug test passes
- Ensure no other tests break
