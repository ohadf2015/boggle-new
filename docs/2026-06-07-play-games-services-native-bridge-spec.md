# Spec — Native Play Games Services (PGS) bridge

**Date:** 2026-06-07
**Status:** implementing
**Context:** Play Console PGS config done (both Android credentials created, 4/6 setup tasks; see memory `play-games-services-config-2026-06-07`). The ❌ remaining "Add the PGS SDK to production APK" task is *code* — this spec.

## Goal
Let the Android app use Google Play Games Services (sign-in, achievements, leaderboards) from the existing web React code. App is a **remote-URL Capacitor WebView shell** (`server.url: https://www.lexiclash.live`, not a TWA), so the bridge must be a real Capacitor plugin whose JS half imports cleanly into the remote Next bundle and whose native half is generated by `cap sync`.

## Plugin choice
`@openforge/capacitor-game-connect@^5` — only actively-maintained option (last publish 2026-03), fullest API, future iOS Game Center path. **Known risk:** its peer is `@capacitor/core ^5` while we ship 8 → scoped peer override; native compile under Cap 8 is the open risk only a device build clears.

### Real plugin contract (designed against, not guessed)
```ts
signIn(): Promise<{ player_name: string; player_id: string }>;
submitScore({ leaderboardID: string; totalScoreAmount: number }): Promise<void>;
unlockAchievement({ achievementID: string }): Promise<void>;
incrementAchievementProgress({ achievementID: string; pointsToIncrement: number }): Promise<void>;
showLeaderboard({ leaderboardID: string }): Promise<void>;
showAchievements(): Promise<void>;
getUserTotalScore({ leaderboardID: string }): Promise<{ player_score: number }>;
```
Export: `import { CapacitorGameConnect } from '@openforge/capacitor-game-connect'`.

## In scope (verifiable this session)
- Add dependency + scoped peer override.
- `utils/nativePGS.ts` — module singleton mirroring `utils/nativeOAuth.ts`:
  `initializePlayGames()`, `isPlayGamesAvailable()`, `signInPlayGames()`, `submitLeaderboardScore()`, `unlockAchievement()`, `incrementAchievement()`, `showLeaderboard()`, `showAchievements()`, `__resetForTesting()`. All `isNative()`-guarded (Android-only via `isAndroid()`), dynamic `import()`, graceful errors (never throw to caller — return a result object), typed against the real contract.
- `hooks/usePlayGamesServices.ts` — thin React hook: availability flag + bound actions, lazy init on first use.
- TDD `utils/__tests__/nativePGS.test.ts` — web no-op, android init, sign-in success/cancel, score/achievement param mapping, error handling, double-init idempotency.
- Achievement/leaderboard IDs sourced from a config map (empty until console-defined) — bridge passes IDs through; **no hardcoded IDs**.

## Out of scope (documented handoff — NOT verifiable here)
- `cap sync` + gradle compile + on-device PGS sign-in (Cap ^5-vs-8 native risk).
- Defining achievements/leaderboards in Play Console (separate console step; tabs currently empty).
- Publishing the PGS project (outward-facing; parked until explicit go).
- Wiring real game-end events → `submitLeaderboardScore`/`unlockAchievement` (follow-up once IDs exist).
- iOS Game Center (plugin supports it; PGS console is Android — defer).

## Invariants
- **Auth orthogonality:** PGS `signIn()` is a Games-scoped flow, kept fully separate from the Supabase/`nativeOAuth` identity session. No token routing between them, no cross-trigger.
- **Web/iOS safety:** every export is a no-op returning a typed "unavailable" result off-Android. The remote web bundle must build and run with the plugin absent at runtime.

## Gates
`tsc` (contract conformance) · `vitest` (bridge logic) · `npm run build` (JS imports into remote bundle) · `npm run lint`.
