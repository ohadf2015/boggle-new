## What's working well
- **KEEP_TIMEOUT_PARTIALS** rescued 25 files across 2 nights that would have been total losses. Zero gate-poisoning incidents. The mechanism is the single biggest improvement this week.
- **Phase 0 intel brief** eliminated live MCP data calls from lane prompts. Lane 04 (100% ship) and 07 (100% ship) both consume brief data without MCP. The principle is sound; stale sources limit value.
- **Lane 04 + 07 architecture** proves that MCP-free lanes ship reliably. Both use prompt + WebSearch/WebFetch + local file reads only. This is the design target for underperforming lanes.
- **Autonomy matrix** shipped 6 real fixes without a single revert. The reversibility check works.
- **Founder-directive detection** in the intel brief fast-pathed sealed bid (pre-built → ship same night). Keeps the loop responsive to explicit user asks.

## Friction points
- **MCP cumulative hang is the #1 systemic failure.** Individual 60s per-call timeouts don't prevent cumulative budget exhaustion when 3+ sequential MCP calls hang. Lanes 01/02 make 5-8 MCP calls each → any 2 hangs = timeout. 05-30: even lane 06 (usually 1-2 MCP calls) timed out.
- **Phase 0 stale sources (3/6 collectors dead)** — search, sentry, supabase return 0 signals. Only PostHog+Railway+feedback are live. Brief injection adds overhead (prompt tokens) without proportional value for the dead sources.
- **Lane 05 scope mismatch** — prompt asks for a new landing page from scratch (design + code + i18n + tests). That's 1200s+ of work for Opus. Only ships when scope is pre-reduced (founder-built code, or docs-only).
- **Lane 02 double MCP dependency** — needs both Supabase (schema queries) and PostHog (metrics). Either hanging kills the lane. REST fallback exists for PostHog but not Supabase.
- **Reddit API fully blocked 3 nights** — lane 04 compensates via WebSearch but produces zero Reddit drafts. Reddit research was the original lane 04 value proposition.
- **05-30 mass timeout** — 5/6 lanes failed. Could be machine load, MCP infra degradation, or prompt bloat from brief injection. No clear root cause yet.

## Concrete improvements (ranked by impact x effort)
1. **MCP call budget cap per lane** — add a `MAX_MCP_CALLS=3` env var. After N MCP calls (successful or hung), lane switches to REST/local-only fallback path. Prevents cumulative hang from eating the full timeout budget. Effort: S. Impact: lanes 01/02 ship rate from ~25% to ~50%. File(s): `scripts/nightly/run.sh`, lane prompt preamble.

2. **Kill dead Phase 0 collectors** — remove search/sentry/supabase collectors from Phase 0 (or mark `optional: true` so they don't inject empty sections into brief). Saves ~200 prompt tokens per lane and removes noise. Effort: S. Impact: cleaner brief, marginal timeout reduction. File(s): `scripts/nightly/lib/intel/`.

3. **Lane 02 REST-only fast path** — replace Supabase MCP with direct `curl` to Supabase REST API for pg_stat_statements / index usage / table sizes. PostHog already has REST helper. Eliminates both MCP dependencies. Effort: M. Impact: lane 02 ship rate from 17% to ~60%. File(s): `scripts/nightly/tools/supabase-rest.sh` (new).

4. **Lane 05 scope reduction** — change prompt from "build a new landing page" to "improve an existing page OR write docs/specs for a new one." Scope that fits in 600s. Effort: S. Impact: lane 05 ship rate from 20% to ~50%. File(s): lane 05 prompt.
