## Friction points
- **#1 — Lanes ship code that does not type-check; the gate correctly drops it (4 of 6 completed nights).**
  My first reading of this was wrong and is corrected here: the gate is **not** false-dropping. On 09-10,
  09-14 and 09-15 the log reads `gate-timeout: standalone typecheck tier FAILED (tsc/test:changed) — the
  authored set has a real type/test break`, then `drop-and-re-gate: conclusive typecheck tier named an
  offender`. The baseline-aware path at `run.sh:851` fired every time and on 09-10 explicitly refused to ship
  (`REFUSING baseline-red ship … a new break may be hidden`). **The cause is upstream, in the lane prompts:
  they tell each lane that `npx eslint <changed files>` is a sufficient self-check, and eslint does not
  type-check.** Already in memory as `gauntlet-gate-needs-tsc-2026-09-12`.
- **#1b — The gate's failure output is ~90% environmental noise**, which is why it needs 4–6 retries and a
  separate "conclusive typecheck tier" to name an offender at all: `connect ECONNREFUSED 127.0.0.1:3000` ×96
  and `::1:3000` ×96 (integration tests needing a dev server the isolated gate never starts), plus
  `[vitest] No "init" export is defined on the "@sentry/nextjs" mock` ×18 (a pre-existing broken mock).
- **#2 — `rc=134` (SIGABRT) on the gate, 6 of 6 completed nights.** Logged as "wedged 2700s idle / 5400s
  backstop, or a native toolchain crash". SIGABRT at a 4 GB heap is the tsc/vitest **OOM** signature, not a
  wedge — and the mislabel sends the loop into a 45–90 min retry instead of raising the heap.
- **#3 — The gate phase is now longer than every lane combined.** 09-12: lanes 1h08m, gate **5h20m**.
  09-15: lanes 5h04m, gate **3h28m**. 09-14: gate 2h46m. It re-runs the full lint+test+build 4–6× a night.
- **#4 — Scheduler starvation is lopsided.** Lane 10 kept 7 files on both nights it ran but launched 2/7;
  lane 06 launched 1/7. Meanwhile lane 09 launched 6/6 and kept exactly 1 file every time. The zero-signal
  score is rewarding frequency, not yield.
- **#5 — Telegram feedback is dead at 52 days** (last callback 2026-07-26). Ninth window at zero.

## Concrete improvements (ranked by impact × effort)
1. **Exclude dev-server-dependent tests from the isolated gate** — the gate has no server on :3000, so those
   192 refused connections are guaranteed noise that poison every verdict. Add a vitest exclude (or an
   `NIGHTLY_GATE=1` skip guard) for the suites that dial `localhost:3000`. Effort: **S**. Impact: removes the
   single largest source of gate failure text; directly targets the 4-of-6 code-drop rate. File:
   `scripts/nightly/run.sh` (the `npm run test` invocation at ~`:716`) + `fe-next/vitest.config.ts`.
2. **Fix the `@sentry/nextjs` vi.mock to export `init`** — 18 errors every gate run from one missing export.
   Effort: **S**. Impact: removes a recurring red herring from every failure triage. File: the shared vitest
   setup that mocks `@sentry/nextjs`.
3. **Replace `npx eslint <changed files>` with `npx tsc --noEmit` in every lane prompt's self-check** — this
   is the single highest-impact change available. eslint does not type-check, so a lane declares "clean" and
   the gate then finds a real TS break and drops the night's code. Add to the SPEED/discipline block: *"if you
   touched any `.ts`/`.tsx`, `cd fe-next && npx tsc --noEmit` before declaring done; if red, fix it or
   `git checkout --` the file."* Effort: **S**. Impact: directly targets the 4-of-6 code-drop rate — the
   largest single loss channel in the loop. File: the shared lane-prompt preamble in `scripts/nightly/run.sh`.
4. **Distinguish OOM from wedge on rc=134/124, and raise the gate heap** — grep the gate output for
   `heap out of memory` / `Abort trap` before printing "wedged", and run the gate with
   `NODE_OPTIONS=--max-old-space-size=8192`. Effort: **S**. Impact: kills the 45–90 min retry that fired on
   6/6 nights. File: `scripts/nightly/run.sh`.
5. **Cap gate retries at 2, then alert** — 4–6 full lint+test+build cycles per night buys nothing once the
   first two agree. Effort: **S**. Impact: reclaims 2–4 h/night, ends the night near 03:00 instead of 08:40.
   File: `scripts/nightly/run.sh`.
6. **Score the scheduler on files-kept-per-run, not launch frequency** — lane 10 (7 files/run) launches 2/7
   while lane 09 (1 file/run) launches 6/6. Effort: **M**. Impact: more shipped work per night at zero extra
   runtime. File: `scripts/nightly/run.sh:421` (lane scheduler).
7. **Rewrite the lane 09 prompt** — 1 file kept on 6 of 6 nights is a prompt ceiling, not a scope ceiling.
   Effort: **S**. Impact: raises the only lane directly tied to the revenue priority. File: the
   `09-monetization` lane prompt.
