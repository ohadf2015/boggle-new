## What's working well
- **The lanes are not the problem.** 10-22: six lanes, `rc=0` on every one, no `exit 124`, no idle-kill,
  17 files authored in 88 min. 10-17: eight lanes, all rc=0. Lane execution has been reliable for two
  straight windows. Every failure this window was downstream of the lanes.
- **The Mandatory-Minimum-Artifact floor is the loop's only unbroken guarantee** — `lane-*-<date>.md`
  landed on 5/5 lane-running nights, including all five whose code was dropped. It is the reason the
  window has a readable history at all.
- **Per-tier gate escalation does not wedge.** lint → typecheck → typeonly → 1-file all run to a verdict.
  The escalation machinery is correct; what it asks is the wrong question (Improvement #1).
- **Preflight divergence → isolated ship (shipped 10-12) held 5/5 nights.** Founder WIP was left
  byte-identical every time lanes ran. That change is still the best infra delta this loop has made.

## Friction points
1. **The gate asks an impossible question, 5/5 nights.** `fe-next/app/[locale]/layout.tsx:4` imports
   `@/lib/i18n/messagesManifest.json`, which `fe-next/.gitignore:133` excludes and only `npm run build:i18n`
   generates. The gate's clean-HEAD worktree runs `build:schemas` and nothing else, so `tsc --noEmit` is
   **unconditionally red in any fresh checkout**. Affects every lane equally. Cost this window: 5 nights of
   code, plus ~5.5 hours of gate wall-clock producing no information.
2. **`lane N` is an execution index, not a lane id.** On 10-22, `lane 2 — kept 3` sits under
   `headless: lane=11-mode-qa`; `lane 4 — kept 4` under `lane=05-landing`. The nightly report inherits it
   (`### Lane 2 — Engagement` and `### Lane — Mode QA` on the same night). Any per-lane metric read from the
   keep lines is wrong, which is why this table had to be reconstructed by hand from the `lane=` lines.
3. **The peel loop has no shrink check and no attempt cap.** 10-18 ran 10 attempts over 98 min, seven of
   them on the *same single file*, every one FAIL. 10-21 repeated the shape 12:40→14:17+. Each 1-file
   typecheck attempt costs ~17 min and, with Friction #1 live, cannot ever go green.
4. **A non-master HEAD aborts the entire run.** 10-19 and 10-20 died at 01:00:0x on
   `not on master (on fix/sentry-2026-10-18)`. Logs are 10 and 20 lines. The "retry in 180 min" never
   produced a second log either night. The isolated gate already builds its own clean worktree — the main
   checkout's branch is irrelevant to it.
5. **~~Zero MCP servers on every lane~~ — checked, not a real finding.** `rg -o "lane=.* MCP scoped → .*"`
   on 10-22 shows real scopes: `01-triage → posthog,sentry,supabase`, `02-perf → posthog,supabase`,
   `03-engagement → posthog`, `05-landing → mcp-image,posthog`, `11-mode-qa → posthog`. `(none)` appears
   only for `07-self-learn` and `12-telemetry-coverage`, both prompt-only lanes. The open question is
   narrower: do `supabase`/`sentry` *connect* after being scoped? Verify next run.
6. **Nobody replays the salvage.** Five nights of dropped code sit on disk with `restore-salvaged-code.sh`
   ready and no step that calls it.
6b. **`docs/nightly/reports/` is gitignored (`.gitignore:82`).** Every lane's STEP-6 `### Lane N` section —
   the loop's primary human-readable output and the entire evidence base lane 7 reads each week — is
   **never committed.** Only `artifacts/`, `ideas/`, `loop-improvements/` and the ndjson ledgers ship. A
   machine wipe erases the history; no reviewer can read a nightly report. Found while verifying this
   lane's own append landed.
7. **A zero-code ship prints as success.** All three of this window's shipped commits verified with
   `git show --stat`: `d37545770` (10-17) = 12 files, all `docs/`; `40dddbcd1` (10-18) = 16 files, all
   `docs/`; `c2712f82a` (10-21) = **one line** of `restore-queue.ndjson`. Each printed `isolated-shipped`.

## Concrete improvements (ranked by impact × effort)
1. **Add `build:i18n` to every isolated-gate `tsc` chain.** Insert `npm run build:i18n && ` after each
   `npm run build:schemas && ` in `scripts/nightly/lib/gate-isolated.sh` lines **142, 160, 173, 203** —
   **four sites.** Last week's note said three; line 833 is the test-only chain
   (`test:backend`/`test:frontend`), not a `tsc` chain, so adding it there fixes nothing. `build:i18n` is
   `tsx scripts/build-i18n-assets.ts` (`package.json:15`), standalone and independent of `build:schemas`.
   **The risk is not syntax** (the inserted string has no quote or `$`) — it is that nobody has confirmed
   `build:i18n` *succeeds* in the gate's clean-HEAD worktree. If it needs something that worktree lacks, a
   parseable TS2307 becomes an earlier unparseable chain failure, which is strictly worse than today.
   **Run the chain by hand in a throwaway worktree once, then ship.** Effort: **S**. Impact: plausibly
   converts 0/7 shipping nights to ~5/7 and removes ~65 min/night of gate wall-clock.
   File(s): `scripts/nightly/lib/gate-isolated.sh`.
2. **Run lanes from an `origin/master` worktree when HEAD is a non-master branch.** Same move that fixed the
   divergence case: build the worktree, leave the founder checkout untouched, never abort. Effort: **S/M**.
   Impact: recovers the 2-of-7 nights that produced literally nothing.
   File(s): `scripts/nightly/preflight.sh`.
3. **Abort the peel loop on no-shrink, cap attempts at 3.** If attempt N's failing-file set is not strictly
   smaller than N-1's, stop and salvage. Effort: **S**. Impact: caps the gate at ~25 min instead of 98 and
   stops burning the night on a question that cannot go green.
   File(s): `scripts/nightly/lib/gate-isolated.sh` (drop-and-re-gate loop).
4. **Print the lane NAME in the keep line and require it in the report heading.** `lane=05-landing — kept 4`
   instead of `lane 4 — kept 4`; lane prompts must emit `### Lane <NN> — <name>` with the zero-padded id.
   Effort: **S**. Impact: makes per-lane success/yield measurable at all — currently it is not.
   File(s): `scripts/nightly/run.sh`, all 12 lane prompts' STEP-append block.
5. **Fail loudly when a ship carries zero code.** If authored code files > 0 and committed code files == 0,
   exit non-zero and put the dropped-path list in the Telegram card. Effort: **S**. Impact: ends the
   "silent success" class — the loop has now mis-reported 2 nights as shipped.
   File(s): `scripts/nightly/lib/git-ship.sh` (or wherever `isolated-shipped` is printed).
6. **Make lane 01's STEP 0 replay the newest unshipped salvage stamp.** One `restore-salvaged-code.sh <stamp>`
   call, gated on #1 being live. Effort: **S**. Impact: recovers 5 nights of already-written, already-reviewed
   code instead of re-deriving it. File(s): lane 01 prompt.
7. **Decide what `docs/nightly/reports/` is.** Gitignored at `.gitignore:82`, so the "report of record"
   every prompt writes to never reaches master. Either un-ignore it (small Markdown, and the most-cited
   source in this file) or point STEP 6 at `artifacts/` instead. Effort: **S**. Impact: lane 7's evidence
   base survives a machine wipe. File(s): `.gitignore:82`, or all 12 lane prompts' STEP 6.
