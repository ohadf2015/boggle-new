# Competitor + viral concepts — 2026-11-14

## Concepts worth borrowing
- **Waffle — pre-filled grid, wrong positions, limited swaps** — source: r/wordgames crosswordle.com/blog/wordle-variants roundup
  - Grid arrives fully filled with the right letters but in the wrong cells; player gets exactly 15 swaps to slot every letter home and complete six valid words.
  - Works because the puzzle is solved-but-scrambled: the "aha" is spatial, not vocabulary recall — a different skill than Boggle/Wordle, so it doesn't cannibalize our existing modes' audience.
  - Fit: word-craft gems mode (`components/word-craft/gems/GemHuntPageClient.tsx`, `lib/word-craft/gems/gemHuntRules.ts`) as a daily variant — gems pre-placed wrong, limited swap budget instead of free-form hunting.
  - Effort: S — reuses the existing gem-grid renderer, new rule-set only.
  - Risk: low; mechanically distinct from Wordle/Boggle, no trademark exposure.

- **Gramlet — progressive letter-claim gates future word length** — source: r/wordgames (`/r/wordgames/comments/1xubv5g/`), live today
  - Daily 8x8 grid, only the edge visible at start; each turn you claim a letter adjacent to ones you already hold, which reveals more of the grid. Letters claimed early determine how long/good your later words can be.
  - Works because it turns "which tile do I pick first" into a strategic bet with a payoff several turns later — classic variable-reward delayed gratification, stronger than instant-score Boggle.
  - Fit: wheel-rush (`backend/modules/wheelRushManager.ts`, `components/multiplayer/WheelRushView.tsx`) — reframe the spin/claim round so early picks open adjacent board territory for later spins, instead of resolving instantly.
  - Effort: M — touches round-resolution state in the backend manager, not just UI.
  - Risk: low; territory-claim is unrelated to the already-pitched rarity-weighted tug-meter mechanic for this mode.

- **Words to Weave — reverse-Boggle grid construction** — source: r/wordgames (`/r/wordgames/comments/1xv536t/`)
  - Player is given a word list and has to FIT the words into a grid, overlapping letters for points — inverse of solving a Boggle board.
  - Works because it's a constructive puzzle (crossword-setter feeling) rather than a search puzzle — different cognitive hook, good for the "calm/untimed" cluster our modeMeta already buckets word-craft into.
  - Fit: word-craft cards mode (untimed `category: 'calm'` per `lib/landing/modeMeta.ts`) as a weekend/special variant.
  - Effort: M — needs an overlap-scoring validator, no new board renderer (reuse crossword's grid primitives).
  - Risk: low.

## What other word-game sites do well
- **Blooket/Gimkit (Khanmigo Blooket Generator)** — teacher types a topic in plain English, gets a ready-to-import game set auto-generated (partnership with Khan Academy, shipped 2026). This is the single biggest classroom-onboarding friction killer in the space: today a teacher must build or pick a word list before a class can play anything. **Education angle (founder priority #3):** our teacher dashboard already has class creation; the gap is word-list creation. An AI-generated "type a topic, get a word list for this class" step on the teacher-side classroom setup flow would mirror this and directly reduces the "teacher never gets a class started" drop-off memory has flagged repeatedly (see `teacher-activation-root-cause` / `newest-teachers-audit` memory).
- **ScrabbleGO** — r/scrabble this week has a top-of-feed complaint thread ("the ads in scrabblego are ridiculous") with visible upvotes. Not a mechanic to steal, but a live positioning data point: ad-fatigue is an active pain point among word-game players right now, worth keeping in mind for any web-ads rollout pacing/frequency decisions (does not override the standing no-touch-the-economy rule — just a timing signal).
