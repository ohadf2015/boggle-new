## Fix 1: Ratify fails open on a bad or missing `decision`

**Source:** Shard 3 #1, `fe-next/app/api/admin/curator-proposals/[id]/ratify/route.ts:39,60`. This one is confirmed from the report's own line citations.

```diff
@@ ~39 @@   (RECONSTRUCTED: place after the existing admin gate)
-  const body = await request.json().catch(() => ({}));
+  const body = await request.json().catch(() => null);
+  const decision = (body as { decision?: unknown } | null)?.decision;
+  if (decision !== 'ratify' && decision !== 'reject') {
+    return NextResponse.json({ error: 'invalid_decision' }, { status: 400 });
+  }
@@ ~60 @@

+  if (decision === 'reject') {
```

If it sends `'approve'` or sends nothing, this diff makes every approval return 400. Either change the caller to send `'ratify'`, or add the real string to the allow-list. ## Fix 2: The persistence lock is per game code for 24 hours, so only round 1 is recorded

## Fix 3: `'constructor' in contentMap` crashes education pages with a 500

**Source:** Shard 1 #1.

- `games-for-teachers/content.ts:523`
- `end-of-year-classroom-activities/content.ts:969,979`
- `games-for-teachers/landing.ts:79`
- `vocabulary-games-classroom/classGames.ts:565`

**Why it matters:** `in` and bare indexing walk the prototype chain. For `/constructor/education/games-for-teachers`, the guard passes and the page receives `Object` instead of content. `c.heroH1.part1` then throws a `TypeError`. `MAP[locale] ??
