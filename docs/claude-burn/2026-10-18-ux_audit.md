## 1. The referral signup wall hides the reward — `fe-next/app/[locale]/referrals/PageClient.tsx:281-310`
- **What the user sees:** A logged-out visitor gets one pink icon, one line of "login required" copy, and two buttons (Sign up and Sign in). The coin rewards and milestone tiers are only rendered at lines 79-161, after login, so the user never sees them.
- **Fix:** Render the milestone ladder (bronze to diamond, with coin amounts) and the "invite friends, earn coins" headline above the buttons. Change the button copy to something like "Sign up to get your invite link". Make Sign up the primary action and Sign in a text link.

## 2. The referral dashboard can end on a blank screen — `referrals/PageClient.tsx:322-337`
- **What the user sees:** If `error === 'unauthorized'`, the error branch is skipped. If `data` is null, line 337 returns `null`, so the user gets a blank page with no header.
- **Related problem:** In the visible error state (lines 322-335), `{error}` prints the raw error string, and retry does a full `window.location.reload()`.
- **Fix:**
  - Replace `return null` with the auth gate or an error card that includes the Header.
  - Show a translated message, not the raw string.
  - Call the hook's refetch instead of reloading the page.

## 3. The Share button silently does nothing on desktop — `referrals/PageClient.tsx:258-276`
- **What the user sees:** If `navigator.share` is missing, or the user cancels, the `'native'` branch falls through. The `'whatsapp'` branch only runs for the other platform, so nothing happens and nothing is shown.
- **Fix:** When native share is unavailable, call `handleCopy` and show the "Copied" toast. Hide the Share button when `navigator.share` is undefined.

## 4. The referral empty state has no call to action — `referrals/PageClient.tsx:185-198, 452`
- **What the user sees:** A new user with 0 referrals sees only a grey "noReferrals" message. The "invite more" nudge at line 452 only shows once `referrals.length > 0`. It also hardcodes `< 50`, which duplicates the milestone threshold.

**Scope.** The files provided contain no signup, pricing, paywall or checkout UI. I have not invented any. The revenue path visible in this code is:

### 1. Duplicate safe-area rules override the Capacitor and AdMob-aware ones
- **Where:** `fe-next/app/animations.css:939-957` overrides `884-902`.
- **What the user sees:**

- **Where:** `animations.css:1214-1215` and `1244-1245`.

  - This card is the "Beat My Score" acquisition artifact.
- **Fix:**
  - Clamp each value, for example `const n = (v) => Number.isFinite(+v) ? Math.max(0, Math.trunc(+v)) : 0`.
  - Wrap the response in `try/catch`.
  - Return a generic branded card as the fallback instead of a 500.

### 4. The word-hunt card fetches an arbitrary `avatarUrl`
- **Where:** `fe-next/app/api/og/word-hunt/route.tsx:72` and `80`.

  - Mixed Hebrew, Latin and digit names (for example "דני2024") will probably come out scrambled. Hebrew-speaking players are a core audience, and a garbled share card undermines the share loop.

### 8. The error screen can show raw translation keys

- **What the user sees:**
  - The `t` helper returns the key path when the cached `en` translation is not loaded or the key is missing.

5. **Guest and player lists show "not found" after a failed fetch** (`GuestManager.tsx:136-141, 296-297`; `PlayerManager.tsx:240-243, 382-383`)
   - **What the user sees:** A failed fetch only raises a toast that disappears. The list falls through to "No guest players found." or "No players found.", which reads as "nobody signed up". Guest-to-signup conversion is the closest funnel signal here.
   - **Fix:** Keep an `error` state. Render a retry panel instead of the empty message. Add a hint to the empty state, such as "Clear filters".

6. **Live monitor hides polling failures** (`LiveMonitor.tsx:173-176, 215, 243-248`)
   - **What the user sees:** After the first load, a failed 5-second poll sets `error`, but it is only rendered when `!data` (`:215`). The pulsing green "LIVE" dot keeps animating over stale numbers, so an outage looks like a quiet day.
   - **Fix:** When `error && data`, show an inline "Reconnecting… last updated hh:mm:ss" banner. Switch the dot to red or grey.

7. **Icon-only controls have no accessible name** (`GuestManager.tsx:417-432, 282-289`; `PlayerManager.tsx:290-297, 414-415`; `InvalidWordsManager.tsx:625-633`)
   - **What the user sees:** Pagination chevrons, the sort-direction arrow and the "dismiss" X are announced as "button" with no name. `title` alone is unreliable.
   - **Fix:** Add `aria-label`s. For the dismiss button, `aria-label={`Dismiss ${word.word}`}`. Add `aria-live` to the sort state.

8. **Inputs use placeholders as their only label, and copy is hardcoded English** (`GuestManager.tsx:231-265`; `PlayerManager.tsx:268-273`; `InvalidWordsManager.tsx:392-400`)
   - **What the user sees:** Screen readers get no label once text is typed. Strings like "Converted", "Block" and "Showing 1-25 of N" bypass `t()`, even though `useLanguage` is imported and the app ships 5 locales. `formatRelative` is also English-only (`GuestManager.tsx:78-89`).
   - **Fix:** Add `<label>` or `aria-label` to each input. Move the strings to i18n keys.

9. **The analytics funnel stops before revenue** (`EngagementFunnel.tsx:38-43`; `AcquisitionSources.tsx:119-130`)
   - **What the user sees:** The funnel ends at day-30 return. There is no step for upgraded or paid. Acquisition counts sources but not which ones convert. The red/lime coding is by colour only (`:72`, and `RetentionHeatmap.tsx:19-25`).
   - **Fix:** Add a "paid or lead" step, and conversion per source. Pair colour with an icon or text.

10. **Destructive actions use bare `window.confirm`, and the revoke modal isn't a real dialog** (`GuestManager.tsx:164`; `PlayerManager.tsx:88`; `MilogWordsManager.tsx:483-540`)
    - **What the user sees:** After a block succeeds, the Block button stays active and nothing marks the row as blocked, so you can block twice. The revoke overlay has no `role="dialog"`, no focus trap, and no Escape or backdrop close.
    - **Fix:** Use the existing UI-kit Dialog. Flip the row to a "Blocked" state after success.

# UX audit: admin surfaces only

Nothing in this batch is on the signup, checkout or player path. Every file is under `components/admin/`. I could not audit the landing page, auth, pricing or paywall UI, so the "closest to revenue" ordering below only covers what I was given. The paid-teacher (edu) funnel is the nearest thing to revenue here, so it comes first. Please send the public and paywall components for an audit that matters more.

1. **`fe-next/components/admin/edu-dashboard/EduKpiGrid.tsx:37-39,57-63`: the revenue KPI is hidden when it is zero.**
   - "Trials converted to paid" and "Pro trials started" are collapsed into a "Quiet metrics" `<details>` whenever current and prior are both 0. In the early days that is exactly when you need to see them.
   - Fix: pin `trialsStarted` and `trialsPaid` as always-visible tiles, and show "0" with a hint such as "No trials yet".

2. **`eduDashboardShared.tsx:50-55` and `EduFunnelCard.tsx`: the funnel stops before money.**
   - The steps are Requested → Approved → Class → First student. There is no trial or paid step, so the biggest-leak verdict can never point at the payment step.
   - Fix: add `trial_started` and `paid` steps, which the KPI grid already has data for.

3. **`EduRescueList.tsx:14,25-27`: a failed load looks like "No one is stuck at this step."**
   - `verdict` is `null` while loading or on error, so `rows` is empty and the reassuring empty message shows. You could miss teachers who are about to churn.
   - Fix: accept `loading` and `error` props, render a skeleton and an error with retry, and show the empty text only on a real empty result.

4. **`EduRescueRow.tsx:96,115-117`: you can't identify a teacher, and the email action can fail silently.**
   - `row.name ?? '—'` gives a nameless row with nothing to identify it. Fall back to the email address.
   - The Email link calls `void log('email')` on click. If logging fails, no notice is shown. The log also fires even if no mail client opens, so the 7-day cooldown can lock out a nudge that was never sent.
   - Fix: show the notice for the email path too, and surface errors.

5. **`EduRescueRow.tsx:91,105` (also `PlayerSelector.tsx:131`, `WordFilters.tsx:35,40`): the layout breaks in RTL.**
   - These use `pl-8`, `text-right`, `left-3` and `pl-9`, but the app ships Hebrew. Icons and padding land on the wrong side.
   - Fix: use `ps-8`, `text-end`, `start-3` and `ps-9`.

6. **`EduVerdictHero.tsx:26-32`: the no-data state is a dead end.**
   - It says only "Not enough data in this window yet", with no next step.
   - Fix: add an action, such as widening the time window or a link to Teacher access.

7. **`DailyWordManager.tsx:92,100` and `WordListEditor.tsx:41`: native `alert()` for errors and success.**
   - It blocks the page, gives no retry, and is inconsistent with the toasts used elsewhere. A failed save can leave the Daily Challenge, which is a retention loop, without a word for a day.
   - Fix: use `toast` as in `BlockListManager.tsx:94`. Also add a fetch-error state to `ScheduleManager.tsx:144`, because a failed load currently looks like "No words scheduled".

8. **`ScheduleManager.tsx:123-128` and `WordListEditor.tsx:111-117`: edit and delete buttons are invisible on touch devices.**
   - They use `opacity-0 group-hover:opacity-100`, so on a phone you can't see them. The delete button has no `focus:opacity-100`, so keyboard users can't see it either.
   - Fix: make them always visible at low opacity, and add `focus-visible:opacity-100`.

9. **Destructive actions without confirmation, and silent errors.**
   - **`BulkActions.tsx:56-70`:** "Reject Selected" fires immediately, with no confirmation.
   - **`BlockListManager.tsx:208-217`:** Unblock has no confirmation.
   - **`BlockListManager.tsx:66-68`:** a load failure shows the "no blocks" empty state.
   - **`CommunityWordsManager.tsx:72-75`:** a failure and an empty result look the same.
   - **`WordCard.tsx:97`:** `new Date('')` renders "Invalid Date".
   - **`BlockListManager.tsx:130,141,149,157`:** the `<label>`s have no `htmlFor`, so they are not associated with their inputs.
   - Fix: add an `AlertDialog` as in `WordListEditor.tsx:128`, separate error from empty, and guard the date.

10. **`ConnectionsReviewPanel.tsx:39-47,102-104,111`: no loading or error state, and wrong counts.**
    - `fetchReviews()` has no catch and no loader, so a failure leaves you looking at all-unreviewed puzzles and you may overwrite real verdicts.
    - `savedMsg` never clears and has no `role="status"`.
    - `c.reviewed++` counts every verdict, including unknown ones.
    - Fix: add a loading/error state, disable editing until the load succeeds, and add a `beforeunload` warning while `changed.size > 0`.

Hardcoded English also appears in `CommunityWords*`, `DailyWordManager` and `ConnectionsReviewPanel`, while the edu and blocklist components use `t()`. That is low priority for admin-only screens.
