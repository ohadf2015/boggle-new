# AdMob Implementation Audit — 2026-06-02

Scope: full `@capacitor-community/admob@8.0.0` integration in `fe-next/`. Goal: maximize revenue + stability. Grounded against Google AdMob guidance and the plugin README (see Sources).

## Verdict

The integration is **mature and battle-tested** — bounded load/show timeouts, idempotent settle, WebView repaint kicks, per-surface waterfall units, UMP consent before init, native patches for banner occlusion + refresh no-fill. Most "obvious" gaps are already handled. Remaining items are at the edges: one shipped fix (interstitial preload), the rest documented for the owner.

## Findings

### FIXED this pass — Interstitial preloading (revenue + stability) — HIGH

**Gap:** `useAdMob.showInterstitial` cold-loaded inline (`prepareInterstitial` → `showInterstitial`) on every call, while rewarded ads preload on mount and re-warm after reward. Two costs:
1. **Revenue:** `recordInterstitialShown()` fires *before* fill is known, and the session cap is only `MAX_INTERSTITIALS_PER_SESSION = 4`. A show-time no-fill burned a slot without ever rendering an ad — games 6/9 could silently consume the budget.
2. **Stability:** cold-load latency at show time is exactly the prepare→show race that previously stranded MP players on a blank frame.

**Fix:** mirror the proven rewarded re-warm pattern.
- Preload state (`ready` flag + in-flight promise) moved into `AdMobContext` (per-provider, app-scoped, resets cleanly in tests).
- New `prepareInterstitial()` — idempotent, dedupes concurrent prepares, gated by `shouldPreloadInterstitial()` (ads on AND under session cap AND past warmup).
- `showInterstitial` uses the warm ad when ready (zero-latency show); cold-loads only as a fallback; **records the slot only on a confirmed show** (no-fill no longer burns a slot); re-warms after each dismiss; warms during play on the not-eligible path so the *first* eligible interstitial is also instant.
- `await`-dismiss contract preserved (MP host still gates next-round emit on `showInterstitial()`).

### Report-only — App Tracking Transparency (iOS) — revenue, but native + unverified ship

The plugin auto-triggers ATT at init (`requestTrackingAuthorization` defaults `true`). Without `NSUserTrackingUsageDescription` in `ios/App/App/Info.plist`, the prompt is rejected and the IDFA stays unavailable → iOS serves only non-personalized ads (materially lower eCPM). **Not fixed here:** `ios/` is gitignored and regenerated by `cap sync`, and iOS ship status is unconfirmed (release pipeline + notes are Android-only). When iOS ships, add to `Info.plist` (and persist via a `cap sync` post-hook or committed template):
```xml
<key>NSUserTrackingUsageDescription</key>
<string>We use your activity to show ads relevant to you. You can play fully without allowing this.</string>
```
Also confirm `SKAdNetworkItems` is populated for iOS attribution.

### Report-only — App-open ads (revenue, high footgun) — DO NOT rush

Plugin supports `loadAppOpen()`/`showAppOpen()`/`isAppOpenLoaded()` (v8). Not implemented. App-open ads on cold-start/foreground-resume are a major session-based revenue source, but they are the highest policy/UX risk in the catalog. **Wiring sketch when prioritized:**
- Listen to Capacitor `App.appStateChange` (`isActive` true). Show only on *resume*, never first launch (gives a bad first impression + risks policy).
- Suppress when returning from another fullscreen ad (rewarded/interstitial just closed), during the UMP consent flow, or mid-game. Add a global "fullscreen ad active" guard (reuse the `rewardAdActiveChange` event bus).
- Preload + 1h expiry like interstitials. Frequency-cap (e.g. ≥4 min between, ≤N/session).
- Route through `kickWebViewRepaint()` on close (same SurfaceView teardown class as interstitial).

### Report-only — Rewarded server-side verification (SSV) — fraud surface, acceptable risk

Coin rewards are granted client-side on the `Rewarded` event; a determined user can spoof it. Coins are soft currency, so risk is acceptable and SSV is large scope (AdMob dashboard SSV config + a backend callback endpoint validating the signed AdMob ping). Document; revisit if coin economy is monetized for real money.

### Report-only — `hasNoAds()` is a permanent `false` stub

`AdMobContext.tsx:77` always returns `false` — correct forward-hook for a future "remove ads" IAP / premium tier. No action until that product exists; leaving the call sites wired is right.

### Report-only — init side-effect runs in render body

`AdMobContext` kicks UMP consent + `AdMob.initialize()` inside the render body (ref-guarded to run once). Works, but is an impure render (React concurrent/StrictMode could invoke it without commit). Low ROI to refactor into `useEffect`/lazy state; note only.

### Owner decision — interstitial cadence may be under-monetizing

Current: 3-game warmup, then every 3rd game (6/9/12/15), cap 4/session, counters reset on cold start (in-memory `useRef`). A casual player who plays ≤3 games per launch **never sees an interstitial**. This is plausibly *under*-monetizing. Tunables (owner's call, not changed here): shorten warmup, every-2nd-game, raise cap, add a minimum-time-between (Google recommends ≥1 ad / 2 min — current cadence is already conservative on frequency, generous on warmup). Persisting counters across cold starts would also tighten the warmup giveaway.
