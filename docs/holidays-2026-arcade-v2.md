# Holiday Arcade v2 + holiday preference (owner 2026-11-27)

Owner: "you will need to have auth users to have the option to change the holiday as well. the arcade games should not all be around words but family fun in general and light and funny with good gaming framework".

## A. Holiday on the player's profile (owner 2026-11-27, supersedes the earlier "choose your holiday" setting)
Owner: "dont let users choose their holiday but make it on their profile with small swap holiday icon that will be in the profile."
- No holiday picker anywhere: remove the HolidayToggle from the event card and anywhere else; no "Off" option, no Settings entry.
- The holiday is assigned by location (existing region logic) and shown on the signed-in player's profile: a small holiday badge (menorah / tree art from public/holidays) next to the name or avatar on their own profile page.
- The ONLY way to change it: a small swap icon on that badge, on the player's own profile, that flips Hanukkah ⇄ Christmas. Signed-in only. Saved on the account: `profiles.holiday_key text null check (holiday_key in ('hanukkah','christmas'))`; null = use location. Guests: location only, no swap.
- One source of truth: for signed-in players the profile value (if set) wins; the `lx_holiday` cookie is only a mirror written when the profile value is read or swapped, so the pre-paint script is right on the next load. Swapping updates the html class immediately (no reload) and refetches holiday data.
- Other players' profiles show their holiday badge (no swap icon).

## B. Arcade v2: family games on pixi.js 8 + matter-js (both already installed)
- Kit `lib/holidays/arcade/kit/` + `components/holidays/arcade/kit/`: lazy-loaded pixi Application host (dynamic import, like components/wordTowerV2/WreckCanvas.tsx / adventure ArenaCanvas), fixed-timestep loop, input (tap/drag/flick/keys), sprite atlas loader from `public/holidays/arcade/`, juice (shake, squash/stretch, particles, hit-stop), SFX through the existing sound system, pause on hidden tab, DPR-aware resize, reduced-motion mode (no shake/particles), cleanup on unmount (destroy app, no leaks — test it).
- **Pass & Play**: 1–4 players on one device, names + avatar colours, turns, final podium. Every family game supports it.
- Games (60–90s, one thumb, funny reactions, mascot cameo):
  - Hanukkah **Latke Flip**: pan with 3–5 latkes sizzling; tap a latke to flip when golden (colour/timing ring); perfect flips chain combos; burnt ones puff smoke and the mascot coughs; oil splatter juice.
  - Hanukkah **Dreidel Spin-Off** (matter-js): flick your dreidel into a round arena; spinning dreidels collide and wobble; last one spinning wins the round; landing letter נ/ג/ה/ש(פ in IL) gives a gelt bonus.
  - Christmas **Present Stack** (matter-js): gifts swing on a crane; tap to drop onto a sleigh; tower wobbles; height + style points; topple = funny crash and reindeer facepalm.
  - Christmas **Snowball Splat**: elves, snowmen and a sneaky Grinch-like (original!) gremlin pop up from snow forts; flick snowballs (arc + splat); hitting the mascot by mistake = penalty and a silly face.
- Arcade hub: family games first, word games after, "Pass & Play" badge; server score submit reuses `app/api/holiday/arcade/**` rules (coin cap per day, sanity checks per game).
- Art: `public/holidays/arcade/*.webp` sprites (generated by coordinator, transparent).
- Performance: 60fps on a 4x-throttled phone; bundle — pixi/matter only loaded on game pages.

## C. Graphics bar (owner: "graphics should look better and more impressive")
- No CSS-block art in games. Every game renders generated art: full-bleed portrait background (`public/holidays/arcade/bg-*.webp`, 9:16) + transparent sprites (`spr-*.webp`), with soft lighting overlays, parallax layers, particles (sparks, sugar, snow, oil, confetti), squash/stretch, glow on interactables, eased camera shake.
- Existing six word games get the same treatment: their own painted background, framed play panel, sprite-based props (e.g. Oil for 8 Nights over the stove/menorah scene; Sleigh Spell flying over the painted rooftops) — keep their logic.
- Arcade hub: big cover cards with art, hover/tap tilt, family badge, animated mascot.
- Acceptance: screenshot each game at 390×844 and 1440×900 mid-play; it should look like a shipped mobile game, not a web form.

## D. Fun pass (owner 2026-11-27: "make sure the games are really fun and not too boring and word related")
- The holiday arcade is family games only: remove the 6 word games from the arcade (hub, routes ?g=, server game ids where unused, tests, i18n, cover art references, landing-page game lists → family games). Delete the code; no dead paths.
- Add 2 family games so each holiday has 3: Hanukkah **Sufganiyah Catch** (slide a plate; catch sufganiyot = public/holidays/props-sufganiyah.webp (no hole), dodge burnt latkes, golden sufganiyah = 5s frenzy rain; speeds up; jelly splat on miss), Christmas **Sleigh Dash** (one-tap flap/hold-to-climb sleigh public/holidays/sleigh.webp over bg-rooftops parallax; collect gifts; dodge smoke plumes and swooping owls; near-miss bonus; speed ramps).
- Fun bar per game (all 6), checked by playing, not by reading code:
  1. Fun in the first 3 seconds (no instructions wall; one-line hint overlay that disappears on first input).
  2. Escalation every 10–15s (speed, new object, twist) and at least one surprise event per run.
  3. Failing is funny (mascot reaction, comic sound, slow-mo on the last fall) and fast to retry (one tap, <1s).
  4. Score juice: combo counter, multiplier pops, end screen shows best + "so close!" when within 10% of best.
  5. Runs last 45–90s; difficulty fair for a 7-year-old on run 1 and still challenging for an adult on run 5.
  6. Pass & Play turns feel like a party: big "Player 2, your turn!" handoff, live mini-scoreboard.
- Acceptance: an independent game-designer reviewer plays every game via the Playwright harness (automated inputs + human-like timing), scores each criterion 1–5 with screenshots, and anything under 4 is reworked until it passes.

## E. Multiplayer + projector (owner 2026-11-28: "the games should somehow be a bit more multiplayer and projector games")
- **Projector / TV mode for every arcade game:** a "Play on the big screen" button on the hub and each game's setup. Fullscreen, 16:9, scaled for 1080p and 4K (container/viewport units, not phone px), text and sprites readable from 5 m, high-contrast, no tiny UI; works with mouse/keyboard on a laptop plugged into a projector. Reuse the app's existing TV/fullscreen pieces (useTvFullscreenListener, classroom TV stage patterns) — no second TV system.
- **Phones as controllers (simultaneous play):** the big screen shows a room code + QR; family members join on their phones (no sign-in needed, name + colour) and play at the same time, each with their own plate/sleigh/dreidel/snowball on the shared screen and a live scoreboard. Build it on the existing Socket.IO room infrastructure (backend rooms, join flow, reconnect rules in .claude/rules/60-recurring-pitfalls.md Class 3 — one socket per tab, redialSocket only). At least 3 games must support it (one per holiday minimum; best fits: Snowball Splat, Dreidel Spin-Off, Sufganiyah Catch / Sleigh Dash), 2–8 players. Server is authoritative for scores.
- **Pass & Play stays** for single-device play; the hub offers all three: Solo, Pass & Play, Big screen + phones.
- Fun bar (D) applies to the multiplayer modes too: lobby to first action < 20 s, everyone sees themselves on the big screen within 1 s of input, funny reactions are visible from across the room, end screen = podium on the big screen + "play again" from any phone.
- Acceptance: Playwright harness runs one TV page + 3 phone contexts against a local server, plays a full round of each multiplayer game, screenshots TV at 1920×1080 and phones at 390×844; the reviewer scores the criteria.
- Owner 2026-11-28 on the first party podium ("it must look much better"): every party screen (lobby, in-game, podium; TV and phone) meets the hub's polish — one header, one small QR with short "lexiclash.live + code" text (no URL dumps), holiday backdrop art across the full 16:9, podium blocks with player colours + cheering mascot + confetti, room-sized display type, Play again as the hero action; phone controller full-height in the player's colour. Gated by an independent design review (≥4/5) against the hub screenshots.
